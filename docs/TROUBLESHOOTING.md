# แก้ปัญหาระบบเวชระเบียน วพอ.

## หน้าเว็บเปิดไม่ได้

| อาการ | ตรวจ | แก้ |
|---|---|---|
| แสดงหน้า 404 ของ Cloudflare | คำสั่ง deploy ให้ URL หรือยัง | รัน `npm run deploy` ใหม่ แล้วใช้ URL จากผลจริง |
| หน้าว่าง ไม่มีเมนู | มี error ในคอนโซลเบราว์เซอร์ไหม | เปิด DevTools แท็บ Console ดูข้อความแดง |
| สไตล์ไม่ขึ้น | ไฟล์ `dist/public/index.html` มี `<style>` ครบไหม | รัน `npm run build` ใหม่แล้ว deploy ซ้ำ |

## ล็อกอินไม่ได้

| อาการ | สาเหตุที่เป็นไปได้ | ตรวจอย่างไร |
|---|---|---|
| `ยังไม่ได้ตั้งค่าการเชื่อมต่อ Google` | Cloudflare ยังไม่มี secret | `npx wrangler secret list` ต้องเห็นทั้งสองคีย์ |
| `เชื่อมต่อ Google ไม่สำเร็จ` | `GAS_WEB_APP_URL` ยังว่าง หรือสคริปต์ยังไม่ deploy | ลองเปิด URL สคริปต์ในเบราว์เซอร์ ต้องได้ JSON |
| เปิด URL สคริปต์แล้วขึ้น `การเข้าถึงถูกปฏิเสธ` | deployment ยังไม่ได้ตั้ง Who has access เป็น `Anyone` | เปิดโปรเจกต์สะพาน > Deploy > Manage deployments > แก้ > Who has access: **Anyone** |
| `ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง` | รหัสผ่านสั้นกว่า 7 ตัวอักษร หรือ `PasswordHash` ไม่ตรง | คำนวณแฮชใหม่ตามขั้นที่ 2 ใน `docs/INSTALL.md` |
| `ลองเข้าสู่ระบบหลายครั้ง กรุณารอ 15 นาที` | ใส่ข้อมูลผิด 5 ครั้ง | รอ 15 นาที หรือลบคีย์ `CF_LOGIN_<แฮชชื่อผู้ใช้>` ใน Script Properties |
| `บัญชีไม่มีสิทธิ์ใช้งาน` | `Role` ในชีต Users ไม่ใช่ค่าที่ระบบรับ | ต้องเป็น `ADMIN`, `MEDICAL`, `STAFF` หรือ `VIEWER` |

## ค่า `GAS_BRIDGE_SECRET` สองฝั่งไม่ตรงกัน

อาการคือทุกคำขอได้ `คำขอไม่ผ่านการยืนยัน` หรือ `ดำเนินการไม่สำเร็จ`

```bash
# ฝั่ง Cloudflare
npx wrangler secret put GAS_BRIDGE_SECRET
# ฝั่ง Google: build ซ้ำด้วยตัวแปรเดียวกัน
GAS_BRIDGE_SECRET='<ค่าเดียวกัน>' SPREADSHEET_ID='<id ชีต>' npm run build
```

ค่าต้องเหมือนกันทุกตัวอักษร ยาวอย่างน้อย 32 ตัวอักษร และต้องตรงกันทั้งสองฝั่ง

ถ้าตั้งค่าใน Script Properties ของสคริปต์แทน ค่าใน Script Properties จะถูกใช้แทนค่าที่ฝังไว้ในโค้ด เวลาตั้งค่าผิดวิธีให้ลบคีย์นั้นออก ไม่ใช่แก้ค่าให้ตรง เพราะค่าใน Script Properties จะทับค่าที่ฝังไว้เสมอ

ข้อความ `ยังไม่ได้ตั้งค่ารหัสลับของสะพาน` แปลว่าทั้งสองทางไม่มีค่าเลย คือไม่ได้ฝังตอน build และไม่ได้ตั้งใน Script Properties

## ข้อมูลไม่เปลี่ยนแปลงหลังบันทึก

| สาเหตุ | ตรวจ |
|---|---|
| บัญชีเป็น `VIEWER` | ระบบจะปฏิเสธการบันทึกด้วยข้อความ `สิทธิ์อ่านอย่างเดียว` |
| ข้อความมีสูตรหรือสัญลักษณ์ต้นหรือท้าย | ระบบปฏิเสธข้อความที่ขึ้นต้นด้วย `=`, `+`, `@` หรือมี `<` `>` เพื่อกันการแทรกสูตรในชีต |
| เขียนชีตไม่ได้ | บัญชีเจ้าของสคริปต์ต้องเปิดสิทธิ์แก้ไขชีตฐานข้อมูลนั้น |

## หน้า LINE LIFF ใช้ไม่ได้

| อาการ | ตรวจ |
|---|---|
| `กรุณาเข้าสู่ระบบ LINE ก่อนใช้งาน` | ผู้ใช้ยังไม่ได้กดเข้าสู่ระบบ LINE ในหน้านั้น |
| `ตัวตน LINE ไม่ถูกต้องหรือหมดอายุ` | LIFF ต้องขอสิทธิ์ `openid` และค่า `LINE_LOGIN_CHANNEL_ID` ต้องตรงกับ Channel ID จริง |
| `บัญชี LINE ยังไม่ผูกกับรหัสนักเรียนนี้` | ผู้ดูแลต้องเพิ่มแถวในชีต `LineBindings` (คอลัมน์ A = LINE user id, B = รหัสนักเรียน 7 หลัก) |
| ค้นด้วยรหัสแล้วไม่พบ | ตรวจว่า `NumberOrOrder` ในชีต `ServiceRecipients` เก็บรหัส 7 หลักจริง |
| หน้า LIFF ขาว หรือเปิดแล้วไม่ขึ้น | Endpoint URL ต้องเป็น `<Worker URL>/?page=liff` และค่า `liffId` ต้องไม่ว่าง |
| `getLiffConfig` คืน `liffId` เป็นค่าว่าง | ยังไม่ได้ใส่ `LINE_LIFF_ID` ตอน build หรือยังไม่ได้อัป `Backend.gs` เวอร์ชันใหม่ |
| เปิด LIFF ได้แต่คนอื่นใช้ไม่ได้ | LINE Login channel ยังเป็น Developing ต้องกด Publish |

## Telegram ไม่ส่งข้อความ

การแจ้งเตือนส่งจาก Cloudflare Worker จึงต้องมี secret สองตัวนี้

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
```

1. ตรวจรายการด้วย `npx wrangler secret list` ต้องเห็นทั้งสองชื่อ
2. ทดสอบด้วย `<Worker URL>/api/telegram/test`
3. ถ้าได้ `"ok": true` แต่ไม่ได้รับข้อความ ให้ตรวจว่า chat ID ถูกตัว และบอทไม่ถูกบล็อก

ข้อมูลหลักจะยังถูกบันทึกแม้การแจ้งเตือนล้มเหลว

## การตรวจว่าระบบปลอดภัย

```bash
npm test
```

ผลที่ต้องเห็นคือผ่านทั้งหมด 9 รายการ ครอบคลุมการป้องกันคำขอซ้ำ การแก้ไขลายเซ็น การปฏิเสธคำสั่งที่ไม่อยู่ในรายการ การปฏิเสธเซสชันปลอม การกรองสูตรในข้อมูล และการไม่ฝังรหัสผู้ดูแลไว้ในหน้าเว็บ

## ดูบันทึกการทำงาน

- Cloudflare: `npx wrangler tail` เพื่อดูคำขอและข้อผิดพลาด
- Google: เปิดโปรเจกต์สะพาน > Executions เพื่อดูรายละเอียดการทำงาน

ข้อความผิดพลาดที่ส่งกลับให้ผู้ใช้ถูกกรองแล้ว ไม่มี URL ภายในหรือค่าความลับหลุดออกไปถึงหน้าเว็บ
